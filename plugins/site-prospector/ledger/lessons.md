- build: **Lenis smooth-scroll should be gated to fine-pointer (desktop) devices — `if (!RM && matchMedia('(pointer:fine)').matches)`.** On iOS/touch, Lenis's virtual scroll can run PAST the real content bounds, so scrolling to the extremes drops the user into empty page-background space (footer stranded mid-screen, then a fully blank screen) — looks like a bad glitch. The DOM is contiguous (measuring scrollHeight vs last-section bottom shows ~0px phantom space), which is the tell that it's the smooth-scroll layer, not the layout. Native mobile scroll is already smooth and correctly bounded, so just don't run Lenis there. - build: **iOS Safari root-scroll "falls into a dark void" at the extremes — the real fix is a nested `<body>` scroller, not `overscroll-behavior`.** On a dark-themed page, iOS rubber-band overscroll past the top/bottom reveals the page background and looks broken (footer stranded mid-screen with the fixed back-to-top button floating = the tell it's overscroll, not a real gap; verify by scanning every element's bottom vs `scrollHeight` — 0px extra means it's not layout). `overscroll-behavior:none` on html/body only tamed the TOP on real iOS (bottom still bounced). What actually clamps both ends: make `<body>` a nested scroller on mobile — `@media(max-width:1000px){ html{height:100%;overflow:hidden} body{height:100%;overflow-y:auto;-webkit-overflow-scrolling:touch} }`. iOS clamps a nested scroller hard at its content edges. Consequences to handle: (1) `position:fixed` nav/back-to-top still pin to the viewport (body scrolling doesn't create a fixed containing block) — good; (2) window scroll events stop firing, so any `addEventListener('scroll', …, window)` / `window.scrollY` / `window.scrollTo` must switch to `document.body` on mobile (back-to-top show-state + click); (3) `ScrollTrigger.batch` reveals (window-based) silently never fire → invisible content; (4) `scrollIntoView` still works and honors `scroll-margin-top`; (5) the native pull-to-refresh gesture is gone (it's a root-scroller gesture) — if the user wants it, re-add a tiny custom one: on `touchstart/move/end` when `document.body.scrollTop<=0` and the drag is downward, translate a fixed brand spinner with the finger (damped ~0.5) and `location.reload()` on release past ~66px; only `preventDefault` once you own the top-pull so normal scroll/upward-swipe is untouched. Side effect: the iOS address bar no longer auto-hides (stable viewport) — acceptable. — set 2026-07-20 ET
- build: **for scroll-reveals on a lazy-image page, use IntersectionObserver, NOT a scroll-event position sweep.** `<img loading="lazy">` below the fold loads as you scroll and grows the page (a junk-removal client grew ~7060→8400px), so an element's position is a moving target and the document bottom keeps receding. A sweep that only runs on scroll EVENTS misses the moment a late image-load pushes the last element into view without a scroll event → it's stranded hidden (the classic symptom: only the very last one or two reveals, e.g. a footer/contact block, stay invisible). IntersectionObserver recomputes on layout shifts too, so it catches it. Use `{root:null, rootMargin:'0px 0px 300px 0px', threshold:0}` (generous positive bottom margin pre-reveals; NEGATIVE bottom margins strand page-bottom elements that can't scroll far enough to satisfy them). Test by scrolling THROUGH while chasing the growing bottom — teleporting to a stale max both skips middle content and stops short of the true (post-load) bottom, producing false failures. — set 2026-07-20 ET
